# quantum-forest-planning

Code, synthetic-data generators and results for the report
**“Quantum Computing Across the Latvian Forest Management Pipeline”**
(DatZD028 Project 2, University of Latvia, 2026) by Muhammad Sajjad Hossain.

The experiments compare classical and (simulated) quantum methods on forest
harvest-planning problems:

- **Stand selection** — choose stands to harvest so that no two neighbouring
  stands are cut in the same period (maximum weighted independent set).
- **Multi-period scheduling with even flow** — five periods, each stand cut at
  most once, and each period's volume within ±10% or ±5% of a target.

All forests are **synthetic**: they are generated by the scripts from fixed
random seeds, so no external data are needed.

> **Scope.** The quantum experiments use 12–14 qubits and exact, **noiseless**
> simulation on a normal computer. They are small-scale proof-of-concept and
> formulation evidence, not evidence of practical quantum performance or
> quantum advantage.

## Quick start

### Option 1 — Google Colab (no installation)

1. Open <https://colab.research.google.com> and choose **File → Upload notebook**.
2. Upload `Quantum_Forest_Experiments.ipynb` from this repository.
3. Click **Runtime → Run all** (about 4–5 minutes).

The notebook is a shorter version of the full experiments, with explanations.

### Option 2 — run the full experiments locally

Requires Python 3.10 or newer. All files are in the top-level folder; the
scripts read and write their results (`.json`) and figures (`.png`) in that
same folder.

```bash
git clone https://github.com/muhhossainsajjad-lgtm/quantum-forest-planning.git
cd quantum-forest-planning
pip install -r requirements.txt
bash run_all.sh            # full run, about 35–40 minutes on a laptop
```

Or run the steps one by one:

```bash
python 01_single_forest_study.py   # ~7 min
python 02_benchmarks.py A          # ~2 min   classical results matrix
python 02_benchmarks.py B          # ~12 min  even-flow complexity (30 s limit per solve)
python 02_benchmarks.py C          # ~20 min  quantum methods over 20 forests
python 02_benchmarks.py D          # ~3 min   QAOA with even flow
python 03_analyze.py               # summary statistics + result figures
python 04_diagrams.py              # concept diagrams
```

Steps A–D are independent and can run in parallel. Re-running overwrites the
reference results in the folder; copy them first if you want to compare, or
set `DATA_DIR` / `OUT_DIR` to write elsewhere.

## Methods in brief

**Synthetic forests.** Stands are placed uniformly at random in a unit square.
Two stands are neighbours if their centres are closer than a radius chosen to
give about five neighbours per stand (a unit-disk graph). Timber volumes are
drawn uniformly from 50–300 m³. Seeds are fixed in the code (for example
`seed = 100 * n + s` in part A). These are the author's modelling assumptions,
not real LVM data.

**Classical methods.** Exact mixed-integer programming with HiGHS (via
`scipy.optimize.milp`), a greedy heuristic, tabu search and simulated annealing.

**Quantum methods (simulated).**
- *QAOA* at depth p = 1–4, exact state-vector simulation in NumPy with COBYLA
  optimisation (random restarts plus warm starts). It is validated against
  Qiskit's `QAOAAnsatz` (state fidelity 1.000; see `01_single_forest_study.py`
  and notebook Part 6).
- *Rydberg (neutral-atom) adiabatic sweep*, simulated inside the
  independent-set subspace (perfect blockade), with detuning swept over
  T = 5, 20 and 60 (units of 1/Ω).

**Measures.**
- Valid-plan rate.
- Success ratio: the share of samples or runs that are exactly optimal.
- Approximation ratio.
- **TTS₉₉ = ln(0.01) / ln(1 − success ratio)**, the number of samples or runs
  needed for a 99% chance of seeing the optimum.

TTS₉₉ counts samples or runs, not wall-clock time. A Rydberg sample, a
simulated-annealing run and a QAOA execution have very different costs.

## Reproducibility notes

- **Deterministic quality results.** All random choices use fixed seeds.
  Re-running the scripts reproduces every plan, success ratio and
  approximation ratio exactly. This was checked by re-running parts A, C and D
  from a clean copy and comparing with the reference `.json` files.
- **Small numerical variation in script 01.** The QAOA optimisation on the
  14-qubit forest can follow a slightly different path between runs because
  of floating-point rounding in multi-threaded linear algebra. In a test
  re-run, success and valid-plan probabilities changed by at most about one
  percentage point (for example 83.5% vs 82.1% valid plans at p = 3, P = 1.5).
  The values quoted in the report and the conclusions are unchanged.
- **Timings vary by machine.** Wall-clock times (including whether HiGHS
  proves optimality within the 30 s limit in part B) depend on the computer
  and on library versions.
- **Versions used for the report:** Python 3.13, NumPy 2.5, SciPy 1.18
  (HiGHS), NetworkX 3.6, Matplotlib 3.11, Qiskit 2.5 (Qiskit is only needed
  for the cross-check).
- **Limitations:** synthetic instances, small instance counts (3–20 per
  setting), noiseless quantum simulation, open-source solver with a short
  time limit. See Section 7.7 of the report.
